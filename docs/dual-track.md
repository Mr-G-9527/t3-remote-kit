# 双轨分工 · T3 远程线程面 vs 本地 IDE 面

> **读者**：所有在这台机器上工作的 agent。决定「这个任务在哪开」时先读这段；不确定就问人。
> **owner**：本文件管**分工判据与交接协议**；机器侧 current 值由 `skills/t3-code-ops/SKILL.md` §0 拥有。

---

## 0. 一句话

T3 = **异步 / 远程 / 持久线程**面；本地 VSCode / 交互式终端 = **交互式 IDE**面。

**同一个任务只在一面开。** 不要两边各起一半，也不要因为「手机能管」就把 IDE 面废掉。

**默认在本地。** T3 需要**正向触发**（命中 §1 的 T3 条目之一），不是「没有理由留在本地就去 T3」。

---

## 1. 判据

### 走 T3 thread（命中任一条即走）

1. 需要**手机**接手、围观或批准
2. 预计**无人值守 > 30 分钟**
3. 需要**跨设备续做**（本地 session 进程死即消失；T3 thread 持久）
4. 交付物是**给人看的**（HTML / 报告 / PR / 裁决单）
5. 需要**多线程并行**（每线程一个 worktree，隔离天然）

### 留在本地 IDE / 终端

1. 需要 IDE 内联：编辑、断点、扩展、跳转定义
2. 高频小步改码、逐行看 diff、翻日志
3. 交互式 shell：长跑进程、管道交互、TUI
4. 生产数据写操作
5. 依赖本地端口调试、真实终端宽度或本地 GUI

### 判据冲突时

- 命中「走 T3」条目 → 走 T3（哪怕 IDE 需求存在：用交接文件 + T3 内 terminal/diff）
- 两条都不命中 → 留本地
- **T3 内没有代码编辑器**（只有 diff / PR 面板 / web PTY）——这是硬约束，不是偏好

## 2. 交接协议

### 2.1 T3 不能接管已在跑的本地 session

换面 = **新建 thread + 交接**。交接的是**状态与上下文**，不是进程本身。

### 2.2 交接文件

路径：`docs/handoff/<YYYY-MM-DD>-<slug>.md`。最小五块：

```text
目标       一句话
已知事实   路径 / 命令 / 结论，带证据
已做/未做
下一步     第一条可执行命令
预判疑问   接收方可能问的问题 + 已给的默认答案
```

### 2.3 可见性（**静默失败高发点**）

T3 thread 的 workspace 默认 `worktree`（独立 checkout）。坑的准确边界：

- **交接文件未提交** → worktree 里读不到 → 交接静默降级成「按缺前提开工」
- **交接文件已提交** → worktree 从当前 HEAD 拉，文件**可见**

三条路，任选其一，**必须显式决定**：

1. **默认**：thread 跑在项目目录（不加 `--worktree`）→ 未提交文件直接可见
2. 用 worktree → **交接文件必须先 commit**
3. 读不到（ENOENT）→ **兜底**：把五块内容内联进 thread 第一条消息，不许静默开工

### 2.4 回问协议（0–3 轮）

人不监控时，交接必须在 **0–3 轮交互**内对齐。

- 接手方先**自解**交班条里的「预判疑问」（0 轮）
- 只对**阻塞项**回问（1–3 轮）
- **超过 3 轮仍未对齐 = 交接失败**：说明五块没写够 → 补交班条，不是延长对话

### 2.5 寻址

交接链路用 **thread id** 寻址（`t3 thread show/send`），不依赖 peer 角色表：
线程侧未必装了角色表，硬凑角色名会多一轮回问。

---

## 3. 不做

- 不让同一个任务在两面同时进行
- 不把「手机能管」当成废掉本地 IDE 的理由
- 不用权限档替代文本约定（权限档只保证「能跑完」，不保证「守规矩」）
- 不用 `approval-required` 开给手机的线程（手机端批不了，线程会卡死）
